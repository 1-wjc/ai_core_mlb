# RAG 사용 전후 답변 품질 비교 (F2015)

> 같은 모델에 같은 질문을 RAG 없이 / RAG로 물어 사실 정확성 · 근거 제시 · "모른다" 응답을 비교.
> 실행: 2026-10-22 · 모델 `gpt-5.4-mini` (GMS) · 임베딩 `text-embedding-3-large` · 질문 12개 · 각 1회 실행

## 1. 비교 방법

| 항목 | RAG 없이 | RAG 사용 |
|---|---|---|
| 입력 | 시스템 프롬프트 "MLB 기록 전문가, 한국어로 짧게, 질문한 항목만" + 선수 이름 + 질문 | 이 서비스의 LangGraph (retrieve → generate). 메타데이터 + 기록 데이터 + 위키백과 + 지표 사전 근거, 프롬프트 3 |
| 정답 기준 | Lahman 원기록으로 계산한 값(`data/processed/record_docs.json`)과 수집한 위키백과 문서 | 같음 |
| 판정 | ✅ 정확 · 🟡 일부 틀림 · ❌ 틀림 · ⭕ 근거에 없다고 답함(모른다) | 같음 |

질문은 네 유형으로 고름: ① 유명 선수의 대표 기록, ② 덜 알려진 선수 · 시즌의 세부 기록, ③ 이 서비스가 계산하는 지표(FIP · 피타고리안 등), ④ 근거가 없는 질문.

**정리**

- 유명 선수의 대표 기록(타율 · 평균자책점 · 월드시리즈 결과)은 RAG 없이도 대부분 맞힘. 모델이 2025 시즌 결과까지 알고 있었음.
- 차이는 **덜 알려진 선수 · 세부 기록 · 계산 지표**에서 크게 남. RAG 없이는 그럴듯한 수치를 지어냈고(Q10 · Q11 · Q12), 유명 선수의 시즌 승수도 틀림(Q2 18승 → 실제 21승).
- RAG 답변은 모든 수치를 근거 문서에서 그대로 인용해 확인할 수 있었고, 서술(Q6 부상 경과)도 위키백과 근거로 날짜를 정확히 댐.
- RAG 없이 답한 값이 공식 값과 같고 RAG 값이 다른 경우가 한 번 있었음(Q1). 원인은 아래 4장.

## 4. 해석과 한계

- **Q1의 FIP · ERA+ 차이**: RAG 없이 답한 3.10 · 179는 FanGraphs · Baseball-Reference가 발표한 값과 같음. 이 서비스는 같은 정의를 쓰지만 FIP 상수와 리그 평균자책점을 Lahman 리그 합계로 직접 계산해 3.06 · 178이 나옴. RAG는 근거 문서의 값을 그대로 인용하므로 "근거와 일치"는 하지만 공식 발표 값과는 소수점 · 1 차이가 남. 지표 사전(FIP 항목)에 이 차이를 적어 둠.
- **모델이 아는 범위가 넓음**: 유명 선수의 대표 기록 · 최근 시즌 결과는 RAG 없이도 맞히는 경우가 많았음. RAG의 이점은 ① 덜 알려진 기록 · 계산 지표의 정확성, ② 모든 답에 출처를 댈 수 있다는 점, ③ 틀릴 때 그럴듯한 수치를 지어내지 않는다는 점에서 나타남.
- **응답 시간**: RAG는 검색어 추출 · 검색 · 생성 3단계라 더 오래 걸림. 두 방식 모두 GMS 응답 지연으로 20초대가 섞임(같은 시간대 측정).
- **한 번 실행한 결과**: LLM 답변은 실행마다 조금씩 달라질 수 있음. 같은 질문을 다시 실행하면 RAG 없이의 오답 항목이 바뀔 수 있지만, RAG 답변은 같은 근거를 인용하므로 수치가 안정적.
- **근거 없는 질문(Q8)**: 이번에는 두 방식 모두 지어내지 않았음. RAG는 근거를 찾지 못했다는 이유를 명시하고 인용 근거를 0개로 표시(F2007 · F2008).

## 5. 재현 방법

- RAG 사용 (`src/`에서 실행): `python -m scripts.ask <선수ID> "<질문>"` (예: `python -m scripts.ask pelhacd01 "2018년 시즌 등판 수, 이닝, 평균자책점, FIP는?"`)
- RAG 없이: 같은 모델에 위 1장의 시스템 프롬프트 + `선수: <이름>\n질문: <질문>` 을 보냄
- 정답 값: `data/processed/record_docs.json` 의 `rec:<선수ID>:<연도>:regular|post`, `rec:team:<팀ID>:<연도>` 문서
