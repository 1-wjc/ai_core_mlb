### 2.2 근거 문서 수집 — 사전 배치 + 질문 시 보충 (RAG 2)
- **사전 배치** (`collect/04`): 항목 선수 전원의 본인 한/영 위키 문서를 미리 수집한다. 본인 문서는 선별 없이 항상 색인한다. 결과는 문서 JSON과 `wiki_manifest.json`(선수별 검색어 · 수집 문서 · 버린 후보 · 수집일)이다.
- **질문 시 보충** (`rag/collector.py`): 선수 위키 근거 중 가장 가까운 거리가 0.33보다 멀면(근거 부족) 프롬프트 1의 영어 검색어 2개로 영어 위키를 검색한다. 프롬프트 2가 후보 제목 · 요약을 보고 고르면 본문 · URL을 수집하고, 문서 JSON · manifest를 저장한 뒤 바로 청킹 · 색인하고 다시 검색한다.
- manifest에 있는 검색어 · 문서는 다시 수집하지 않는다 (NF2002).

### 2.5 범위와 항목 선정 기준
- **항목 선정**: ① 범위 안 AL · NL 출장 기록 ② Chadwick → Wikidata 외부 ID 정확 일치 ③ 한국어 · 영어 위키 문서가 모두 있음
- **시즌 범위**: 처음에는 **1990\~2025**로 진행했다 (범위 선수 8,813명 → 항목 1,466명). 필수 · 심화 기능을 이 범위로 완성한 뒤 **1901\~2025로 확장**했다 (범위 선수 19,200명 → 항목 2,047명).
  - 1901 = 아메리칸리그 창설. 이후 AL · NL 두 리그 체제가 지금까지 이어진다. 19세기는 리그 구성 · 기록 항목이 달라 제외했다.
  - 확장 이유: 루스 · 윌리엄스 같은 레전드 선수 질문이 가능해지고, 1990년 이전 기록이 잘리던 선수(놀런 라이언 · 칼 립켄 등)의 통산이 온전해진다.
  - 초기 시즌은 도루 실패 · 희생플라이 · 상대 타자 수 등이 비어 있다. 그 값을 쓰는 지표는 분모가 0이면 계산하지 않는다.
  - 규정 타석 · 이닝은 그해 팀 경기 수 기준이다 (154경기 시대 · 파업 · 단축 시즌 자동 반영).
  - 구단 이름은 그 시대 이름으로 쓴다 (보스턴 브레이브스 · 브루클린 다저스 · 몬트리올 엑스포스).

## 3. 파이프라인

### 3.1 정규화 — 영화 팩과 같은 두 가지 모양으로 맞춤
원천(Lahman)은 여러 테이블 · 시즌 시계열 · 숫자 위주라 제공 영화 팩과 형식이 다르다. 그대로 쓰면 "컬렉션 2개", "항목 1건 = 텍스트 1개"(F2001 · F2002)에서 벗어나므로 색인 전에 정규화한다.

- **`players.json`** (movies.json 역할, `build/01`): `player_id`, `name_ko`, `name_en`, 데뷔 · 마지막 시즌, 포지션, 투타, 소속 팀 이력(그 시대 이름) · 프랜차이즈(구단 필터용), 수상, 통산 대표 지표, 최고 시즌, 포스트시즌, **특징 문장**(계산값으로 규칙 기반 생성, LLM 미사용 — 줄거리 역할을 해서 의미 검색 · 조건 탐색을 가능하게 함)
- **`record_docs.json`** (외부 문서 컬렉션의 기록 데이터, `build/02`): 선수×시즌 정규시즌 · 포스트시즌, 팀×시즌 1행 = 문서 1개. 지표는 `build/metrics.py`로 로컬 계산 (OPS+ · ERA+ 는 리그 기준값 + 구장 보정, FIP 상수는 리그 · 시즌별)
- **`season_leaders.json`** (`build/03`): 연도별 홈런 · 타율 · 평균자책점 · 탈삼진 1위와 MVP · 사이영상. 서비스 항목이 아닌 선수까지 Lahman AL · NL 전체 기준 (메인 시즌 타임라인)
- **역할 규칙**: 출장 경기가 가장 많은 포지션이 투수면 투수, 아니면 타자. 투수의 타격 · 야수의 짧은 등판은 문서 text에서 뺀다 (값은 stats에 보관). 투타겸업(투수이면서 야수 출장 100경기 이상, 또는 타자이면서 100이닝 이상)은 둘 다 표시 → 오타니 쇼헤이 · 베이브 루스
- **외부 문서 JSON** (영화 위키 JSON과 같은 스키마): `page_id, title, url, text, source, player_id, related_player, search_query, collected_at`

### 3.2 컬렉션
| 컬렉션 | 내용 | 청크 ID |
|---|---|---|
| `player_meta` | 선수 1명 = 텍스트 1개 (대표 지표는 메타데이터 필드로도 저장 → 숫자 필터) | `player_id` |
| `player_docs` | `source`: 기록 데이터(Lahman, 1행 = 1청크) / 영어 · 한국어 위키백과(1000자 · 겹침 200자) / 지표 사전(지표 1개 = 1청크) | `player_id:문서ID:순번` (지표 사전은 `_glossary`) |

### 3.3 실행 흐름
1. **사전 준비**: Lahman · Chadwick · Wikidata 수집 → 정규화(`build/01~03`) → 위키 본인 문서 수집(`collect/04`) → 색인(`rag/indexer.py`: 메타데이터 · 기록 · 위키 · 지표 사전)
2. **retrieve 노드**
   - 선택 선수 메타데이터는 ID로 직접 가져와 항상 근거 1번
   - 프롬프트 1이 검색어 JSON 배열 출력 (직전 대화로 "그 해" 같은 표현을 풀어 씀)
   - 기록 문서: 선수 범위 안에서 검색, 질문에 연도가 있으면 그 시즌만 (Top 3)
   - 구단 시절 합산: 질문에 구단이 나오면 그 구단 시즌 기록을 코드로 합산해 근거 추가 (`rag/team_era.py`)
   - 위키: 선수 범위 안 MMR 검색 (후보 30 → λ 0.7로 4개). 가장 가까운 거리가 0.33보다 멀면 질문 시 보충 수집(프롬프트 2) 후 다시 검색
   - 지표 사전: 질문 · 검색어에 지표 이름 · 별칭이 나오면 추가 (최대 3)
   - 병합 · 중복 제거 → 근거 번호
3. **generate 노드** (프롬프트 3): 근거만 사용, 수치는 기록 데이터 근거 우선, 직접 계산 금지, 없으면 "확인되지 않는다". 비교 · 사실 확인은 규칙을 덧붙임. 답변에서 `[근거 N]` 추출, "확인되지 않는다"는 답에서는 인용 제거
4. **화면**: 근거 목록을 먼저 보여 주고 답변을 스트리밍. 실제 인용한 근거만 출처 종류 · 원문 링크 · 원문 미리보기와 함께 표시

### 3.4 숫자 처리 원칙 (RAG가 숫자에 약한 이유에 대한 대응)
| 약점 | 대응 |
|---|---|
| 임베딩은 숫자 크기를 구분하지 못함 · 숫자만 다른 청크 혼동 | 선택 선수 메타데이터 항상 포함, 질문 연도로 기록 문서 필터, 청크에 선수명 · 시즌 표지 |
| 비교 · 범위 · 정렬 불가, Top-k만 봄 | 숫자 조건은 메타데이터 필터로 처리 (F2011), 구단 합산은 코드로 |
| 청킹이 표를 깨뜨림 | 기록은 시즌 1행 = 문서 1개, 열 이름 포함 |
| LLM 계산 실수 | 지표는 코드로 계산, LLM은 인용만. 답변 숫자 ↔ 근거 숫자 대조 검사는 *예정* (추가 기능 C1) |

### 3.5 지표 계산과 지표 사전
- **계산**: `build/metrics.py`가 빌드 시점에 계산해 기록 문서 · 항목에 넣는다 (LLM 미사용, 분모 0이면 계산하지 않음). 구단 시절 합산만 retrieve 노드 안에서 원기록을 합쳐 다시 계산한다 (2노드 유지).
- **지표 사전**: `build/metrics.json`의 지표 38개마다 한/영 이름 · 별칭 · 적용 대상 · 계산식 · 리그 상수 필요 여부 · 좋은 방향 · 설명 · 참고 위키 문서. 질문에 별칭이 나오면 근거로 붙는다 (지표 설명에 근거를 댐).
- **범위**: 타율 · 출루율 · 장타율 · OPS · OPS+ · ISO · BABIP · RC · BsR 등 타격 19개, ERA · ERA+ · FIP · WHIP · K/9 · K-BB% 등 투구 14개, 수비 2개, 팀 3개. wOBA · wRC+ · WAR는 리그별 가중치 · 수비 · 대체 선수 기준이 필요해 제외.

### 3.6 한국어 질문 → 영어 문서
선수 ID 필터로 후보를 좁히고, 프롬프트 1이 뽑은 검색어로 검색한다. 위키 청크에는 `[선수: 류현진 · 영어 위키백과 · Hyun-jin Ryu]` 같은 표지를 붙인다. 임베딩 `text-embedding-3-large`는 한/영 같은 뜻 문장 코사인 0.446 (small 0.417). 질문 시 보충 수집의 위키 검색은 영어 검색어만 사용한다 (한국어 위키 검색 후보는 무관한 문서 위주, 실측).
